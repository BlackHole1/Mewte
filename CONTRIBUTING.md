# Contributing to Mewte

Thank you for taking the time to help. Bug reports, ideas, translations and code are all welcome. By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting bugs and proposing changes

- Search the [existing issues](https://github.com/BlackHole1/Mewte/issues) first.
- For a bug, describe what you did, what you expected and what happened. Include the Mewte version, the database you use and the relevant lines of the run log. Never paste a token.
- For a larger change, open an issue before writing code so we can agree on the direction.
- Report security problems through [private vulnerability reporting](https://github.com/BlackHole1/Mewte/security/advisories/new), not in a public issue.

## Development setup

You need [Bun](https://bun.sh) 1.4 or later. Docker is needed only for the PostgreSQL and MySQL tests.

```bash
git clone https://github.com/BlackHole1/Mewte.git
cd Mewte
bun install
bun run dev
```

`bun run dev` starts the API on <http://localhost:3000> and the web app on <http://localhost:5173>. Open the second address; it proxies `/api` to the first. Data goes to `apps/server/data`, which Git ignores.

### Trying it without a real GitHub token

The repository contains a small stand-in for the GitHub API with sample notifications:

```bash
bun apps/server/src/testing/demo.ts
```

In another terminal:

```bash
GITHUB_API_URL=http://localhost:3999 DATA_DIR=./data/demo DATABASE_URL=sqlite://./data/demo/mewte.db bun run dev
```

Connect an account with the token the first command prints.

## Project layout

| Path | Contents |
| --- | --- |
| `packages/shared` | zod schemas, shared types and the rule engine. Pure code with no I/O. |
| `packages/db` | Database access with Kysely for SQLite, PostgreSQL and MySQL, plus migrations. |
| `apps/server` | The Hono API, the GitHub client, the scheduler and the runner. |
| `apps/web` | The React interface (Vite, Tailwind CSS, coss ui, react-i18next). |
| `docs/i18n/<locale>` | Translations of the documentation. |

## Checks

Run these before you open a pull request. CI runs the same commands.

| Command | What it does |
| --- | --- |
| `bun run lint` | Lints with oxlint. |
| `bun run fmt` | Formats with oxfmt. `bun run fmt:check` only verifies. |
| `bun run typecheck` | Type-checks every workspace. |
| `bun run test` | Runs the tests with Vitest, using SQLite. |
| `bun run build` | Builds every workspace. |

To run the database tests against PostgreSQL and MySQL as well:

```bash
docker compose -f compose.test.yaml up -d
cp .env.test.example .env.test
bun run test:all
```

## Guidelines

- **Tests**: changes to the rule engine need tests for the new behavior. Bug fixes should come with a test that fails without the fix.
- **Databases**: every query must work on all 3 databases. Follow the conventions in `packages/db` (string ids generated by the app, timestamps as epoch milliseconds, no `RETURNING`), and add a new migration instead of editing one that has been released.
- **API**: define request and response shapes as zod schemas in `packages/shared` and register routes with `@hono/zod-openapi` so the OpenAPI document stays accurate. API descriptions are written in English.
- **Interface text**: no hardcoded copy in components. Add a key to `apps/web/src/i18n/locales/en.json` and to the other 7 locale files. A test fails when the files drift apart.
- **Interface components**: use the coss ui components in `apps/web/src/components/ui` and their color tokens. Check both the light and the dark theme.
- **Commits and pull requests**: write titles in English and in the imperative mood ("Add label condition"). Keep one pull request to one topic and explain why the change is needed.

## Translations

Interface languages live in `apps/web/src/i18n/locales/<locale>.json`. To improve a translation, edit the file for that language. Keep the keys and the `{{placeholders}}` exactly as in `en.json`.

To add a language, add its code to `LOCALES` in `packages/shared/src/constants.ts`, add the locale file and the language name in `apps/web/src/i18n/index.ts`, and translate the documents into `docs/i18n/<locale>/` using the same file names. Each document starts with the language bar; add the new language to that bar in every document.

The English documents in the repository root are the source of truth. When you change one, update the translations or mention in the pull request which ones still need an update.
