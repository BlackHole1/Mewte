# Участие в разработке Mewte

Спасибо, что нашли время помочь. Мы рады сообщениям об ошибках, идеям, переводам и коду. Участвуя в проекте, вы соглашаетесь соблюдать [Кодекс поведения](CODE_OF_CONDUCT.md).

## Сообщения об ошибках и предложения изменений

- Сначала поищите среди [существующих issue](https://github.com/BlackHole1/Mewte/issues).
- Если это ошибка, опишите, что вы сделали, чего ожидали и что произошло. Укажите версию Mewte, используемую базу данных и относящиеся к делу строки журнала запусков. Никогда не вставляйте токен.
- Если изменение крупное, откройте issue до того, как писать код, чтобы мы могли согласовать направление.
- О проблемах безопасности сообщайте через [приватное сообщение об уязвимости](https://github.com/BlackHole1/Mewte/security/advisories/new), а не в публичном issue.

## Настройка среды разработки

Вам понадобится [Bun](https://bun.sh) версии 1.4 или новее. Docker нужен только для тестов с PostgreSQL и MySQL.

```bash
git clone https://github.com/BlackHole1/Mewte.git
cd Mewte
bun install
bun run dev
```

`bun run dev` запускает API на <http://localhost:3000> и веб-приложение на <http://localhost:5173>. Открывайте второй адрес: он проксирует `/api` на первый. Данные сохраняются в `apps/server/data`, этот каталог Git игнорирует.

### Проба без настоящего токена GitHub

В репозитории есть небольшая заглушка GitHub API с примерами уведомлений:

```bash
bun apps/server/src/testing/demo.ts
```

В другом терминале:

```bash
GITHUB_API_URL=http://localhost:3999 DATA_DIR=./data/demo DATABASE_URL=sqlite://./data/demo/mewte.db bun run dev
```

Подключите аккаунт с помощью токена, который выводит первая команда.

## Структура проекта

| Путь | Содержимое |
| --- | --- |
| `packages/shared` | Схемы zod, общие типы и движок правил. Чистый код без ввода-вывода. |
| `packages/db` | Доступ к базе данных через Kysely для SQLite, PostgreSQL и MySQL, а также миграции. |
| `apps/server` | API на Hono, клиент GitHub, планировщик и модуль выполнения запусков. |
| `apps/web` | Интерфейс на React (Vite, Tailwind CSS, coss ui, react-i18next). |
| `docs/i18n/<locale>` | Переводы документации. |

## Проверки

Выполните их перед тем, как открыть pull request. CI запускает те же команды.

| Команда | Что делает |
| --- | --- |
| `bun run lint` | Проверяет код линтером oxlint. |
| `bun run fmt` | Форматирует код с помощью oxfmt. `bun run fmt:check` только проверяет форматирование. |
| `bun run typecheck` | Проверяет типы во всех рабочих пространствах. |
| `bun run test` | Запускает тесты на Vitest с использованием SQLite. |
| `bun run build` | Собирает все рабочие пространства. |

Чтобы прогнать тесты базы данных ещё и на PostgreSQL и MySQL:

```bash
docker compose -f compose.test.yaml up -d
cp .env.test.example .env.test
bun run test:all
```

## Рекомендации

- **Тесты**: изменения в движке правил требуют тестов на новое поведение. К исправлению ошибки должен прилагаться тест, который без этого исправления не проходит.
- **Базы данных**: каждый запрос должен работать во всех 3 базах данных. Соблюдайте соглашения, принятые в `packages/db` (строковые идентификаторы, которые генерирует приложение, метки времени в миллисекундах эпохи Unix, никакого `RETURNING`), и добавляйте новую миграцию вместо правки уже выпущенной.
- **API**: описывайте форматы запросов и ответов схемами zod в `packages/shared` и регистрируйте маршруты через `@hono/zod-openapi`, чтобы документ OpenAPI оставался точным. Описания API пишутся на английском языке.
- **Тексты интерфейса**: никаких жёстко заданных строк в компонентах. Добавьте ключ в `apps/web/src/i18n/locales/en.json` и в остальные 7 файлов локалей. Если файлы расходятся, один из тестов завершается ошибкой.
- **Компоненты интерфейса**: используйте компоненты coss ui из `apps/web/src/components/ui` и их цветовые токены. Проверяйте и светлую, и тёмную тему.
- **Коммиты и pull request**: пишите заголовки на английском языке в повелительном наклонении («Add label condition»). Один pull request должен быть посвящён одной теме; объясните, зачем нужно изменение.

## Переводы

Языки интерфейса находятся в `apps/web/src/i18n/locales/<locale>.json`. Чтобы улучшить перевод, отредактируйте файл нужного языка. Сохраняйте ключи и `{{placeholders}}` в точности как в `en.json`.

Чтобы добавить язык, добавьте его код в `LOCALES` в файле `packages/shared/src/constants.ts`, добавьте файл локали и название языка в `apps/web/src/i18n/index.ts` и переведите документы в `docs/i18n/<locale>/`, сохранив имена файлов. Каждый документ начинается с панели выбора языка; добавьте новый язык в эту панель в каждом документе.

Английские документы в корне репозитория являются первоисточником. Изменив один из них, обновите переводы или укажите в pull request, какие из них ещё предстоит обновить.
