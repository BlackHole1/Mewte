# Mewte

Mewte поддерживает тишину в ваших входящих на GitHub. Он по расписанию проверяет уведомления ваших аккаунтов GitHub, отмечает как выполненные те, что подходят под ваши правила, и ведёт историю всего, что убрал.

Это инструмент для самостоятельного размещения, рассчитанный на одного человека: вы сами его запускаете, сами в него входите, а ваши токены никогда не покидают ваш сервер.

## Возможности

- **Несколько аккаунтов GitHub**, у каждого свой интервал опроса и кнопка «Запустить сейчас».
- **Правила создаются в браузере**: вложенные группы условий (выполняются все, любое, ни одно или не все) по репозиторию, владельцу, причине, типу, состоянию, заголовку, меткам, автору, ревьюерам, исполнителям, комментаторам и признаку бота. Редактор также показывает всё правило одной фразой, поэтому вложенную логику легко проверить.
- **Issue, pull request и обсуждения**: правила читают подробности всех трёх типов, включая то, есть ли у обсуждения принятый ответ.
- **Предпросмотр, прежде чем довериться правилу**: пробный запуск показывает, какие из текущих непрочитанных уведомлений оно убрало бы, и при этом ничего не меняет.
- **История и журнал запусков** с поиском, фильтрами и настраиваемым сроком хранения. GitHub не может восстановить уведомление, отмеченное как выполненное, поэтому каждая запись истории содержит ссылку на исходный объект.
- **Вход для одного пользователя** с необязательной двухфакторной аутентификацией (TOTP и коды восстановления).
- **SQLite, PostgreSQL или MySQL**. SQLite используется по умолчанию и не требует настройки.
- **8 языков интерфейса**: English, 简体中文, 繁體中文, 日本語, 한국어, Русский, Français, Español. Светлая и тёмная темы.
- **Описание OpenAPI** для HTTP API и интерактивная документация по адресу `/api/docs`.

## Быстрый старт

Вам понадобится Docker с плагином Compose.

```bash
curl -fsSLO https://raw.githubusercontent.com/BlackHole1/Mewte/main/compose.yaml
docker compose up -d
```

Откройте <http://localhost:3000>, создайте аккаунт владельца, а затем:

1. Перейдите в раздел **Аккаунты GitHub** и подключите аккаунт с помощью персонального токена доступа ([как его создать](#create-a-github-token)).
2. Перейдите в раздел **Правила**, создайте правило и нажмите **Запустить предпросмотр**, чтобы проверить, что оно уберёт.
3. Дождитесь следующего опроса или нажмите **Запустить сейчас** у нужного аккаунта.

Данные хранятся в томе Docker `mewte-data`. Делайте резервные копии этого тома: в нём находятся база данных и ключ, которым шифруются ваши токены.

> Если экземпляр окажется доступен другим людям раньше, чем вы пройдёте страницу настройки, сначала задайте `SETUP_TOKEN`. См. раздел [Конфигурация](#configuration).

## Создание токена GitHub

Mewte нужен **классический** персональный токен доступа. Токены fine-grained и токены GitHub App не могут читать уведомления, поэтому GitHub отклоняет их для этой задачи.

1. На GitHub откройте **Settings**, затем **Developer settings**, затем **Personal access tokens**, затем **Tokens (classic)**. Прямая ссылка: <https://github.com/settings/tokens/new?scopes=notifications&description=Mewte>
2. Выберите **Generate new token (classic)**, задайте название токена и срок его действия.
3. Выберите области доступа:

   | Область доступа | Когда нужна | Зачем |
   | --- | --- | --- |
   | `notifications` | Всегда | Чтение уведомлений и отметка их как выполненных. |
   | `repo` | Только для приватных репозиториев | Позволяет правилам читать автора, метки, состояние, ревьюеров, исполнителей и комментарии в issue, pull request и обсуждениях приватных репозиториев. Без неё эти условия никогда не срабатывают для приватных репозиториев. |

4. Если в вашей организации обязателен единый вход SAML, нажмите **Configure SSO** рядом с токеном и авторизуйте его для этой организации.
5. Скопируйте токен и вставьте его в Mewte: раздел **Аккаунты GitHub**, затем **Подключить аккаунт**.

Mewte шифрует токен перед сохранением и больше никогда его не показывает. Когда GitHub перестаёт принимать токен (истёк срок действия или токен отозван), Mewte приостанавливает этот аккаунт и помечает его на странице обзора, пока вы не замените токен.

## Как работают правила

У правила есть название, приоритет, охват аккаунтов (все аккаунты или выбранные) и дерево условий. Действие только одно: «Отметить как выполненное».

- **Порядок**: для каждого непрочитанного уведомления правила проверяются от наименьшего числа приоритета к наибольшему. Срабатывает первое подходящее правило, и именно оно записывается в историю.
- **Группы**: группа задаёт, как сочетаются её условия: выполняются все, выполняется любое, не выполняется ни одно или выполняются не все. Группа может содержать другие группы.
- **Текстовые списки**: условия по репозиторию, владельцу и людям принимают несколько значений. `*` служит подстановочным знаком, поэтому `acme/*` соответствует любому репозиторию `acme`. Регистр при сопоставлении не учитывается.
- **Заголовок**: «содержит» или регулярное выражение, при необходимости с учётом регистра.
- **Отсутствующие данные никогда не дают совпадения**: некоторым условиям нужны данные, которые GitHub не предоставляет для уведомления (например, состояние релиза или сведения о приватном репозитории без области доступа `repo`). Такое условие не истинно и не ложно, и правило, которое от него зависит, не срабатывает даже при инвертировании. Mewte предпочитает не трогать уведомление, чем убрать его по ошибке.
- **Дополнительные запросы только при необходимости**: такие сведения, как метки, ревьюеры или комментаторы, запрашиваются только для тех уведомлений, по которым правило не может принять решение без них, и ненадолго кешируются.

Учитываются только непрочитанные уведомления.

## Конфигурация

Все настройки задаются переменными окружения. При использовании Docker Compose поместите их в файл `.env` рядом с `compose.yaml`; каждая переменная описана в [.env.example](../../../.env.example).

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite://./data/mewte.db` (`sqlite:///data/mewte.db` в образе) | `sqlite://<path>`, `postgres://user:password@host:5432/db` или `mysql://user:password@host:3306/db`. |
| `SECRET_KEY` | создаётся автоматически для SQLite | Ключ, которым шифруются сохранённые токены GitHub, не менее 32 символов. Обязателен для PostgreSQL и MySQL. С SQLite, если переменная пуста, Mewte при первом запуске создаёт `secret.key` в `DATA_DIR`. Сгенерировать ключ можно командой `openssl rand -base64 32`. |
| `SETUP_TOKEN` | не задан | Если задан, страница настройки запрашивает это значение, прежде чем создать аккаунт владельца. |
| `TRUST_PROXY` | `false` | Установите `true`, если Mewte работает за обратным прокси, который задаёт заголовки `X-Forwarded-For`, `X-Forwarded-Host` и `X-Forwarded-Proto`. |
| `COOKIE_SECURE` | `auto` | `auto`, `true` или `false`. При значении `auto` cookie сессии помечается как Secure, если запрос пришёл по HTTPS. |
| `HOST` | `0.0.0.0` | Адрес, на котором сервер принимает подключения. |
| `PORT` | `3000` | Порт, на котором сервер принимает подключения. |
| `DATA_DIR` | `./data` (`/data` в образе) | Каталог, в котором хранится `secret.key` при использовании SQLite. |
| `GITHUB_API_URL` | `https://api.github.com` | Корневой адрес REST API. Для GitHub Enterprise Server укажите `https://<host>/api/v3`. |
| `WEB_DIST` | определяется автоматически | Каталог с собранным веб-приложением. |

Docker Compose также читает `MEWTE_PORT` (порт на хосте, по умолчанию `3000`) и `MEWTE_VERSION` (тег образа, по умолчанию `latest`).

Если изменить или потерять `SECRET_KEY`, сохранённые токены станет невозможно прочитать. Каждый токен придётся ввести заново.

### PostgreSQL или MySQL

В `compose.yaml` уже описаны оба сервера баз данных, они включаются через профили Compose. Создайте рядом с ним файл `.env`:

```bash
COMPOSE_PROFILES=postgres
DB_PASSWORD=<output of: openssl rand -hex 24>
DATABASE_URL=postgres://mewte:${DB_PASSWORD}@postgres:5432/mewte
SECRET_KEY=<output of: openssl rand -base64 32>
```

Для MySQL используйте `COMPOSE_PROFILES=mysql` и `DATABASE_URL=mysql://mewte:${DB_PASSWORD}@mysql:3306/mewte`. Затем выполните `docker compose up -d`.

Чтобы использовать сервер баз данных, который у вас уже работает, задайте только `DATABASE_URL` и `SECRET_KEY`. Mewte создаёт и обновляет свои таблицы при запуске.

Запуск нескольких экземпляров Mewte с одной базой данных поддерживается для PostgreSQL и MySQL: экземпляры координируются через базу данных, поэтому один аккаунт никогда не опрашивается двумя экземплярами одновременно. SQLite рассчитан на один экземпляр.

### За обратным прокси

Если Mewte доступен за пределами вашего компьютера, отдавайте его по HTTPS. Сохраняйте исходный заголовок `Host` (в Caddy и Traefik это поведение по умолчанию; в nginx добавьте `proxy_set_header Host $host;`) и задайте `TRUST_PROXY=true`, чтобы Mewte брал адрес клиента и схему из заголовков `X-Forwarded-*`. Без этого все посетители будут выглядеть пришедшими с адреса прокси и делить один лимит попыток входа.

Mewte отклоняет запросы на запись, у которых `Origin` не совпадает с хостом, по которому к нему обратились. Если за прокси любое сохранение завершается сообщением «Запрос отклонён», значит, прокси переписывает `Host`, а `TRUST_PROXY=true` не задан.

### Обновление и резервные копии

```bash
docker compose pull
docker compose up -d
```

Миграции базы данных выполняются при запуске. Для SQLite делайте резервную копию всего тома `mewte-data` (база данных и `secret.key`). Для PostgreSQL или MySQL делайте резервную копию базы данных и храните `SECRET_KEY` в надёжном месте.

## Запуск без Docker

Вам понадобится [Bun](https://bun.sh) версии 1.4 или новее.

```bash
git clone https://github.com/BlackHole1/Mewte.git
cd Mewte
bun install --frozen-lockfile
bun run build
bun apps/server/dist/index.mjs
```

Сервер слушает порт 3000 и хранит данные в `./data`. Bun загружает файл `.env` из каталога, в котором вы его запускаете.

Чтобы собрать образ Docker самостоятельно:

```bash
docker build -t ghcr.io/blackhole1/mewte:latest .
```

## API

Всё, что делает веб-интерфейс, проходит через HTTP API по пути `/api`. Документ OpenAPI 3.1 доступен по адресу `/api/openapi.json`, а интерактивная документация по адресу `/api/docs`. Запросы аутентифицируются с помощью cookie сессии, которую вы получаете при входе.

## Замечания по безопасности

- Пароли хешируются с помощью Argon2id. При неверном пароле, коде двухфакторной аутентификации или токене настройки ответ приходит только через 2–3 секунды, и с каждой новой ошибкой ожидание растёт. За 15 минут допускается не более 5 неудачных попыток с одного браузера на одном адресе, 20 с одного адреса и 50 на аккаунт; дальнейшие попытки отклоняются до конца этого окна.
- Токены GitHub шифруются с помощью AES-256-GCM и никогда не возвращаются через API.
- Сессии хранятся в cookie с атрибутами HttpOnly и SameSite. Смена пароля завершает все остальные сессии.
- Mewte отправляет токены только на настроенный хост GitHub API.

Чтобы сообщить об уязвимости, воспользуйтесь [приватным сообщением об уязвимости](https://github.com/BlackHole1/Mewte/security/advisories/new) вместо публичного issue.
